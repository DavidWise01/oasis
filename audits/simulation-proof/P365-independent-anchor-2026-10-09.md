# P3.65 — Lost-reservation anchor repair
Date 2026-10-09. A separately provisioned anchor directory holds an exclusive per-witness/context/epoch digest reservation. New signatures require successful atomic creation of this external reservation before interacting with P3.61's primary file. Existing matching reservation permits retrieval of an already committed signature, but never recreates a missing primary signature; incomplete or absent primary is quarantined. Anchor disappearance, corruption, or conflicting digest blocks signing. This is not proof against simultaneous compromise/deletion or rollback of both primary and anchor.
Executed Node 22 local PASS 36 assertions across six storage fault scenarios: deleted, truncated, empty, bad digest, bad signature, stale pending. All rejected conflicting same-epoch signing; all allowed new epoch; only intact primary recovered duplicate. Test provisions the anchor separately to reproduce a previously completed vote. This is a fail-closed model, not a hardened distributed trust service.
