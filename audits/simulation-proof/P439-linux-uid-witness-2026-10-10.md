# ROOT0 P4.39 — Linux operating-system identity boundary (2026-10-10)

Executed in a Linux root-enabled container with Node 22.16.0: **14/14 assertions PASS** on final rerun. `setpriv` launched the witness service under UID **65534** (`nobody`); a signed controller socket request was executed under UID **33** (`www-data`). The controller UID was denied direct read access to the 0600 witness private key and the SQLite witness database inside a 0700 directory. The signed IPC request was accepted, replay was refused, unauthenticated request denied, P4.34 CAS accepted epoch 1 and rejected epoch 3 jump, and a maximum 4-record replay ledger failed closed at capacity. A `SIGKILL` terminated witness after the operations. Dependencies are limited to `p434_cas.mjs` and Node 22 experimental SQLite plus Linux `setpriv`. All source, test and measured JSON are packaged in P4.39 ZIP (SHA256 `cd2d2f8f40fa8af1225d6e1bb556203680e8763a4bdebe7080470842a5a38e97`).

**Limits:** Genuine separate Linux UIDs **on the same machine**, not independent hosts. Root can still access both stores. The Unix socket uses 0666 permissions but Ed25519 application authentication; peer-UID allowlisting and privileged-supervisor process custody remain unimplemented. Replay storage is bounded by failing closed when full (no safe expiry/pruning); no remote independent witness, TPM, trusted monotonic wall-clock or power-cut testing. This audit-only GitHub commit does not include runnable P4.39 source, which remains in downloadable ZIP.
