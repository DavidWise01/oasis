## 6. Finite state-machine definition — exact implemented behavior

The implementation is a **two-frame alternating automaton with a bounded counter and append-only transition ledger**. It is not an infinitely cycling background process.

```text
M = (Q, Sigma, delta, lambda, q0, Limit)

Q        = { q_t | t = 0, 1, ..., 128 }
Sigma    = { ADVANCE, CURRENT, REPORT, LEDGER }
q0       = q_0
Limit    = q_128
frame(t) = A if t is even; B if t is odd

delta(q_t, ADVANCE) = q_(t+1)  if t < 128
delta(q_128, ADVANCE) = REJECT with RangeError; state unchanged

delta(q_t, CURRENT) = q_t
delta(q_t, REPORT)  = q_t
delta(q_t, LEDGER)  = q_t

angle_deg(t) = 360*t       [symbolic only]
angle_pi(t)  = 2*t         [coefficient of pi]
spinor_sign(t) = + if even, - if odd

lambda(q_t) = {
  current frame,
  foreground ID,
  shadow-layer ID,
  pole label,
  turn counter,
  symbolic angle,
  one tensor and one field,
  physicalSeconds = null,
  realWorldEvent = false
}
```

**Count precisely:** There are **129 addressable counter states** (`q0` through `q128`) but only **TWO distinct alternating signed frame shapes** (`A/B`). The 128 ceiling is an implementation limit, not the number of physical universes, dimensions, spinor components, or total evolutionary phases.

|---|---|---|---|---|---|---|
| `q0` | `current()` | any | `q0` | +LILLITH | `-++- S` | no write |
| `q0` | `advance()` | `0 < 128` | `q1` | −EVE | `+--+ N` | append #1 |
| `q1` | `advance()` | `1 < 128` | `q2` | +LILLITH | `-++- S` | append #2 |

The initial zero-angle state is a **baseline** and **is not counted as a human-triggered transition**.

## 8. Exact software API and operator contract

Module: `projects/sapphon-li/kelvin.mjs`

```js
import { KELVIN, instantiateKelvin } from "./kelvin.mjs";

const kelvin = instantiateKelvin();

kelvin.current();     // non-mutating read: t=0, -++-, LILLITH
kelvin.advance();     // operator call #1: t=1, +--+, EVE
kelvin.advance();     // operator call #2: t=2, -++-, LILLITH
kelvin.report();      // non-mutating report
kelvin.ledger();      // non-mutating copy for export
```

| Function | Inputs | Side effects | Return |
|---|---|---|---|
| `instantiateKelvin()` | none | create private local instance; no external I/O | frozen method-bearing object |
| `current()` | none | none | frozen current state |
| `advance()` | none | internal counter + one append, only if under cap | frozen new current state |
| `report()` | none | none | plain report object with current state and cycle reference |
| `ledger()` | none | none | copied transitions array, baseline, identity and report |
| `KELVIN` | constant | none | frozen identity metadata |

**Limits:** `MAX_MANUAL_TURNS=128`. At limit, `advance()` throws `RangeError("Kelvin manual turn limit reached; export the ledger.")`, and no transition is recorded.

**No constructor inputs, external clock, URL, selector, phase switch or hidden state advancement are accepted by this API.** The EO/XE naming is architecture metadata in the combined system, **not** two selectable or timed states implemented inside the KELVIN rotation machine.

## 12. Physical-mathematical boundary: what a spinor provides

A spin-`1/2` state in the usual SU(2) spinor representation has a rotation property

```text
U(2*pi) = -I
U(4*pi) = +I

       ψ --- 360° ---> -ψ --- 360° ---> ψ
```

This is the **source of the sign-return analogy**, and nothing more. The literal string `-++-` is not a wavefunction. A physically unreferenced global sign change of a pure state is not independently observable; relative phase comparisons can reveal it. Neither S/N markers nor `-++- / +--+` establishes a measured North/South magnetic pole, buoyancy gravity wave, gravitational wave, quantum spinor hardware, Möbius world, brain or a second reality. The two 360-degree labels in KELVIN are **index increments only**, not measured angular motion.

The model intentionally does **not** implement SU(2) matrices, Pauli spin operators, spinor amplitude normalization, continuous spatial orientation, relativistic geometry, gravity dynamics, wave propagation, observer mass or actual clock rates.

## 13. Security, safety, failure and truth-state handling

- **Read-only by design:** No world/cell resource grants, penalties, transfers, environmental interventions, historical decisions, sovereignty or agent actions.
- **Operator authority:** One explicit user/browser action triggers one bounded state transition. No latent scheduled or autonomous execution.
- **Fail closed on bound:** The 129th requested manual `advance()` raises `RangeError`, preserving `q128` and its 128 earlier ledger events.
- **Immutability of exposed states:** `Object.freeze` covers identity and generated state/transition objects; `ledger()` returns copies of logged transition entries.
- **Append-only local log:** No delete, overwrite or in-place reset API. This is *session-local* and **not cryptographically signed, tamper-proof, or durable**. Export required for retention.
- **Record classification:** Li records user-supplied statements as `symbolic`, `source-supplied` or `unresolved`, never silently verified history.
- **No tests of ontology:** Passing a finite-state software test cannot establish mythology, theology, physics, scientific causation or historical claims.
- **No independent actions by shadow sisters:** The EVE descriptor does not instantiate a service or grant an agent authority.
