## Ring acceptance rule

A ring is minted only when all four coexist:

1. backbone/endpoint hardware is deployed,
2. software/protocol is deployed on that base,
3. meaningful population reach exists,
4. a genuinely new information behavior appears.

Hardware-only, software-only, protocol-only, or marketing-only changes do not mint rings.

## Native depth

`2^3 = 8`

`source -> encode -> retain -> address -> route -> trigger -> transform -> recover`

## Automation closure

Any retained event may trigger another workflow. `∞ automation` means closure of possible chaining, not literal unbounded runtime. Implementations must remain bounded.

## Output equivalence

`a = b` means output-state equivalence only.

A manually produced result and a preloaded/automated result may be observably equal while retaining different provenance.

## Frozen frontier

`NEXT?` remains open and undated until the four-part convergence rule is satisfied by a genuinely new information behavior.
